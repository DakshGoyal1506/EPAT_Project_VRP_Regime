# Phase 05 - Deterministic Threshold Baseline Regimes

## Status

Complete / frozen.

This phase is implemented, documented, and ready for downstream Gaussian HMM and Markov-regime phases. Future edits should be limited to bug fixes, safety/no-lookahead fixes, reproducibility fixes, documentation updates, or tests for existing behaviour.

## Objective

Phase 5 builds deterministic, interpretable, point-in-time threshold regime labels for US and India.

The phase assigns each available date to one of three canonical economic states:

| State ID | State name |
|---:|---|
| 0 | calm |
| 1 | transition |
| 2 | stress |

The goal is to create a transparent baseline that later HMM, Markov autoregression, MSVOL/MSGARCH, and strategy phases can compare against.

Phase 5 answers:

```text
Can simple threshold filters identify economically meaningful calm / transition / stress regimes?
```

## Phase Boundary

Phase 5 does:

- build threshold-based regime components
- combine components into final threshold regimes
- write component availability flags
- write component blocked reasons
- write final trigger reasons
- produce no-lookahead diagnostics
- produce crisis-window diagnostics
- produce VRP/forward-label-by-state diagnostics

Phase 5 does not:

- train HMMs
- train AR-HMM / Markov autoregression models
- run strategy signal construction
- run backtests
- run broker or IBKR paper-signal logic
- tune thresholds using crisis windows
- force stress labels during known crises
- use forward/ex-post labels as construction features

## Component Filters

Phase 5 builds five component filters.

### 1. IV Percentile Filter

Feature:

```text
iv_ann
```

Rules:

```text
calm       if iv_ann <= prior rolling 50th percentile
stress     if iv_ann >= prior rolling 80th percentile
transition otherwise
```

### 2. RV Percentile Filter

Feature:

```text
rv_gk_22d_ann_lag1
```

Rules:

```text
calm       if lagged RV <= prior rolling 50th percentile
stress     if lagged RV >= prior rolling 80th percentile
transition otherwise
```

### 3. Drawdown Filter

Preferred inputs:

```text
close
adj_close
underlying_close
```

Fallback inputs:

```text
log_return
simple_return
```

Rules:

```text
calm       if drawdown >= -0.07
transition if -0.12 < drawdown < -0.07
stress     if drawdown <= -0.12
```

### 4. IV Slope Filter

Feature:

```text
iv_ann
```

Derived measure:

```text
iv_slope = short_ma(iv_ann, 21) / long_ma(iv_ann, 63) - 1
```

Rules:

```text
calm       if iv_slope <= 0.00
transition if 0.00 < iv_slope < 0.10
stress     if iv_slope >= 0.10
```

### 5. HAR-VRP Z-Score Filter

Feature:

```text
vrp_har_gk
```

Availability rule:

```text
har_forecast_available == True
```

Derived measure:

```text
vrp_har_zscore = (vrp_har_gk_t - prior rolling mean) / prior rolling std
```

Rules:

```text
calm       if zscore >= 0.00
stress     if zscore <= -1.00
transition otherwise
```

## Final Combined Regime

Component states use:

```text
0 = calm
1 = transition
2 = stress
```

The final weighted stress score is:

```text
threshold_stress_score =
    1.0 * iv_percentile_state
  + 1.0 * rv_percentile_state
  + 1.5 * drawdown_state
  + 0.5 * iv_slope_state
  + 1.0 * vrp_har_state
```

Final stress rule:

```text
stress if:
    any hard-stress component is stress
    OR threshold_stress_score >= stress_score_cutoff
```

Hard-stress components:

```text
iv_percentile_state
rv_percentile_state
drawdown_state
```

Final calm rule:

```text
calm if:
    iv_percentile_state == calm
    AND rv_percentile_state != stress
    AND drawdown_state == calm or unavailable
    AND vrp_har_state == calm
    AND threshold_stress_score <= calm_score_cutoff
```

Otherwise:

```text
transition
```

## No-Lookahead and Safety Rules

1. Do not use `rv_gk_22d_forward_ann_label` as a regime feature.
2. Do not use `vrp_forward_expost_gk_label` as a regime feature.
3. Reject construction features containing `future`, `forward`, `expost`, or `label`.
4. Do not use full-sample percentiles for backtest-facing labels.
5. Thresholds at date `t` must use only data before `t`.
6. Use `vrp_har_gk` only when `har_forecast_available == True`.
7. Do not forward-fill or backfill missing HAR forecasts.
8. Do not create strategy signals in Phase 5.
9. Do not run backtests in Phase 5.
10. Do not tune thresholds using crisis windows.

## Notebook

No Phase 5 notebook is required for this cleanup. Any future Phase 5 notebook must be inspection-only and must not recompute regimes, tune thresholds, create strategy signals, or run backtests.

## Known Limitations

1. The threshold baseline is intentionally conservative.
2. Calm may be sparse because calm requires low IV, non-stress RV, non-stress drawdown, calm HAR-VRP, and low aggregate stress score.
3. Crisis windows are sanity-check annotations, not observed training labels.
4. Threshold values are hand-specified and interpretable, not optimized.
5. Daily data cannot identify intraday regime flips.
6. VIX and India VIX are implied-volatility proxies, not direct variance swap quotes.
7. This phase does not prove tradability; strategy construction and backtests belong to later phases.
